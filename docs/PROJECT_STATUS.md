## Gotchas for a fresh session / new machine

- `data/raw/` and `data/processed/` are **git-ignored by default**
  (`.gitignore`), but the processed artifacts needed to keep training
  (`phase0_dataset.npz`, `eligible_records.csv`,
  `baseline_reproduction_fold_results.jsonl`) were explicitly force-added
  and pushed so a fresh clone has them — don't re-run
  `build_dataset.py`/`run_exclusion_cascade.py` unless you're
  intentionally regenerating from raw.
- The raw CTU-CHB `.dat`/`.hea` signal files were **not** pushed (only the
  already-preprocessed `.npz`), so `data/raw/ctu-chb.../` won't exist on a
  fresh clone unless copied separately. Not needed for training — only
  needed if re-running preprocessing from scratch.
- `torch` in `requirements.txt` is unpinned to a CUDA build — on a new
  machine, install requirements, then explicitly reinstall the CUDA wheel
  matching the GPU driver (`nvidia-smi` to check version), e.g.
  `pip install torch --index-url https://download.pytorch.org/whl/cu121`.
  The training code auto-detects CUDA (`torch.cuda.is_available()`), no
  code changes needed.
- `scikit-learn` is now pinned exactly (`==1.7.2`) — keep it pinned;
  unpinning it reintroduces the CV-split irreproducibility in report §2.4.
- If two machines might ever run the training script concurrently against
  *unsynced* copies of the JSONL, they'll duplicate a bit of work at the
  boundary fold — harmless (just wasted compute on one duplicate fold), but
  `git pull` before resuming to minimize it.
