   `docs/exclusion_cascade_report.md`. Result: **N=432 of 552** eligible

   - **Important flagged issue** (see `docs/known_limitations.md`):
     positive-label prevalence collapses under the cascade, from 44/552
     (8.0%) to **only 17/432 (3.9%)**, because a `2000`-series sub-cohort
     with genuine long signal dropouts is disproportionately positive.
     Root-caused and verified against raw signals (not a pipeline bug).
     **Decision made: keep the cascade as frozen, proceed anyway** — do NOT
     relax it to recover positives, that's exactly the protocol-drift trap
     the plan warns against. Consequence: outer CV folds will have ~2-4
     positives each, so per-fold AUROC will be high-variance by
     construction — expected, not a bug. This also means the Phase 5.2
     power analysis must be recomputed for N_pos=17 (not the plan's assumed
     ~40) when we get there.
5. **Preprocessing pipeline built** (`src/preprocessing/`): clipping, gap
   detection, PCHIP interpolation (≤15s gaps), artifact rejection, 1Hz
   downsampling, train-fold-only z-normalisation for FHR, per-record
   min-max for UC, missingness mask as a 3rd channel. Output:
   `data/processed/phase0_dataset.npz`.
6. **5x5 nested, stratified, grouped CV splitter** built
   (`src/cv/nested_cv.py`).
7. **Models implemented**:
   - True Crossformer (`src/models/crossformer.py`) — DSW embedding,
     two-stage (cross-time / cross-dimension) attention, hierarchical
     encoder — this is the baseline being reproduced, B0 in the plan's
     ablation table.
   - Three trivial baselines (`src/baselines/`): logistic regression +
     GBT (XGBoost) on classical CTG features, 1D-ResNet on raw FHR+UC.
8. **Training harness built and made resumable**
   (`scripts/run_baseline_reproduction.py`): runs all 4 models per fold,
   writes each completed fold's result **immediately** to
   `data/processed/baseline_reproduction_fold_results.jsonl` (append-only),
   and on restart automatically skips any `(seed, fold)` pair already in
   that file. `scripts/check_baseline_progress.py` reads the JSONL at any
   time (mid-run or after) and prints partial mean/CI + gate status.

## Gotchas for a fresh session / new machine

- `data/raw/` and `data/processed/` are **git-ignored by default**
  (`.gitignore`), but the processed artifacts needed to keep training
  (`phase0_dataset.npz`, `eligible_records.csv`,
  `baseline_reproduction_fold_results.jsonl`) were explicitly force-added
  and pushed so the GPU laptop's clone has them — don't re-run
  `build_dataset.py`/`run_exclusion_cascade.py` unless you're
  intentionally regenerating from raw.
- The raw CTU-CHB `.dat`/`.hea` signal files were **not** pushed (only the
  already-preprocessed `.npz`), so `data/raw/ctu-chb.../` won't exist on a
  fresh clone unless copied separately. Not needed for training — only
  needed if re-running preprocessing from scratch.
- `torch` in `requirements.txt` is unpinned to a CUDA build — on a new
  machine, install requirements, then explicitly reinstall the CUDA wheel
  matching the GPU driver (`nvidia-smi` to check version), e.g.
  `pip install torch --index-url https://download.pytorch.org/whl/cu121`.
  The training code auto-detects CUDA (`torch.cuda.is_available()`), no
  code changes needed.
- If two machines might ever run the training script concurrently against
  *unsynced* copies of the JSONL, they'll duplicate a bit of work at the
  boundary fold — harmless (just wasted compute on one duplicate fold), but
  `git pull` before resuming to minimize it.
